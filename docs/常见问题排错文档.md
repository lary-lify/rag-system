## 1. 端口占用问题

### 症状

启动服务时报错：`Address already in use` 或 `端口被占用`

### 排查与解决

#### Windows

```cmd
:: 查看端口占用
netstat -ano | findstr "8000"
netstat -ano | findstr "5173"
netstat -ano | findstr "3306"
netstat -ano | findstr "19530"

:: 终止占用进程（替换<PID>为实际PID）
taskkill /pid <PID> /f
```

#### Mac/Linux

```bash
# 查看端口占用
lsof -i :8000
lsof -i :5173
lsof -i :3306
lsof -i :19530

# 终止占用进程
kill -9 <PID>
```

### 修改端口

如果端口被其他服务长期占用，可以修改端口：

**后端**：编辑 `.env` 中 `APP_PORT=8001`，同时修改 `frontend/vite.config.ts` 中的代理目标端口。

**前端**：编辑 `frontend/vite.config.ts` 中 `server.port: 5174`。

## 2. MySQL 连接问题

### 症状1：`Can't connect to MySQL server on 'localhost:3306'`

**原因**：MySQL 服务未启动。

**解决**：

```bash
# Windows
net start MySQL80

# Mac
brew services start mysql@8.0

# Linux
sudo systemctl start mysql
```

### 症状2：`Access denied for user 'root'@'localhost'`

**原因**：密码错误或认证方式不兼容。

**解决**：

1. 检查 `.env` 中 `MYSQL_PASSWORD` 是否正确
2. MySQL 8.0 默认使用 `caching_sha2_password`，如需兼容旧客户端：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'your_password';
FLUSH PRIVILEGES;
```

### 症状3：`Unknown database 'rag_kb'`

**原因**：数据库未创建。

**解决**：

```sql
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS rag_kb DEFAULT CHARACTER SET utf8mb4 DEFAULT COLLATE utf8mb4_unicode_ci;"
```

> 后端启动时会自动建表（SQLAlchemy `create_all`），只需先创建空库即可。

### 症状4：建表报错 `FULLTEXT PARSER ngram` 不支持

**原因**：MySQL 版本过低（<5.7）或 ngram 未启用。

**解决**：
- 升级到 MySQL 8.0+
- 或在 `/etc/my.cnf` 添加：`ngram_token_size=2`

## 3. Milvus 连接问题

### 症状1：`Fail connecting to server on localhost:19530`

**原因**：Milvus Standalone 未启动。

**解决**：

```bash
# 确认 Milvus 进程是否在运行
# Windows
tasklist | findstr milvus

# Mac/Linux
ps aux | grep milvus

# 重新启动 Milvus
./milvus run standalone
```

### 症状2：`collection not found` 或搜索返回空结果

**原因**：知识库未加载向量数据，或 Collection 被误删。

**解决**：
1. 确认文档上传后状态为 `completed`
2. 检查 Milvus 中 Collection 是否正常：

```python
from pymilvus import connections, utility
connections.connect(host="localhost", port="19530")
print(utility.list_collections())
```

### 症状3：Milvus 启动报 Docker 相关错误

**原因**：下载了错误的 Milvus 版本（Docker版而非Standalone版）。

**解决**：前往 https://github.com/milvus-io/milvus/releases 确认下载的是 `milvus-standalone-*` 版本，而非 Docker 镜像。

### 症状4：`pymilvus` 版本不兼容

**原因**：pymilvus 与 Milvus 服务端版本不匹配。

**解决**：

```bash
# 推荐使用 >=2.5.5 版本
pip install pymilvus>=2.5.5
```

### Milvus 本地 vs 云端切换

如需切换云端 Milvus（Zilliz Cloud / 阿里云等），修改 `.env`：

```bash
# 本地
MILVUS_HOST=localhost
MILVUS_PORT=19530
# MILVUS_TOKEN=      本地版不需要

# 云端（示例：Zilliz Cloud）
# MILVUS_HOST=in01-xxxxx.api.gcp-us-west1.zillizcloud.com
# MILVUS_PORT=19530
# MILVUS_TOKEN=your-cloud-token-here   云端才需要
```

## 4. Python 依赖问题

### 症状1：`ModuleNotFoundError: No module named 'xxx'`

**原因**：依赖未安装或虚拟环境未激活。

**解决**：

```bash
# 进入 backend 目录
cd backend

# 激活虚拟环境
# Windows
venv\Scripts\activate
# Mac/Linux
source venv/bin/activate

# 重新安装依赖
pip install -r requirements.txt
```

### 症状2：pip install 超时或速度慢

**解决**：使用国内镜像源。

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 症状3：`pymilvus` 安装失败（Windows）

**原因**：缺少 Visual C++ 编译工具。

**解决**：
1. 下载 Microsoft C++ Build Tools：https://visualstudio.microsoft.com/visual-cpp-build-tools/
2. 安装时勾选"Desktop development with C++"
3. 重新 `pip install pymilvus`

### 症状4：`aiomysql` 报错

**解决**：

```bash
# macOS 可能需要安装 openssl
brew install openssl
export LDFLAGS="-L/usr/local/opt/openssl/lib"
export CPPFLAGS="-I/usr/local/opt/openssl/include"
pip install aiomysql
```

## 5. API 调用报错

### 症状1：通义 Embedding API 返回 401/403

**错误信息**：`Invalid API-key provided` 或 `Authentication failed`

**排查**：
1. 检查 `.env` 中 `TONGYI_API_KEY` 是否正确
2. 确认 Key 是否有余额/未过期
3. 确认已开通"灵积模型服务"

**验证**：

```bash
curl -X POST "https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings" \
  -H "Authorization: Bearer <你的KEY>" \
  -H "Content-Type: application/json" \
  -d '{"model":"text-embedding-v3","input":["测试文本"],"dimensions":1536}'
```

### 症状2：DeepSeek API 返回 401/403

**排查**：
1. 检查 `.env` 中 `DEEPSEEK_API_KEY` 是否正确
2. 确认 Key 余额充足
3. 确认网络可访问 `api.deepseek.com`

**验证**：

```bash
curl -X POST "https://api.deepseek.com/v1/chat/completions" \
  -H "Authorization: Bearer <你的KEY>" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"你好"}],"max_tokens":10}'
```

### 症状3：API 返回 500 Internal Server Error

**排查步骤**：

1. 查看后端控制台日志，找到具体错误堆栈
2. 常见原因：
   - 数据库连接断开 → 检查 MySQL 是否运行
   - Milvus 连接断开 → 检查 Milvus 是否运行
   - API Key 无效 → 参考上面步骤验证
   - 文件解析失败 → 检查上传文件格式是否支持

### 症状4：CORS 跨域错误

**前端控制台出现**：`Access to XMLHttpRequest has been blocked by CORS policy`

**解决**：
- 开发环境：Vite 已配置代理（`/api → localhost:8000`），检查 vite.config.ts
- 生产环境：确保后端 `main.py` 中 CORS 中间件已正确配置

## 6. SSE 流式无打字效果

### 症状1：对话发送后无任何响应

**排查**：

1. 打开浏览器开发者工具 → Network 标签
2. 找到 `/api/conversations/chat` 请求
3. 查看请求是否返回200，是否为 `text/event-stream` 类型

### 症状2：SSE 返回但前端无逐字显示

**原因**：可能是一次性返回全部内容，而非流式。

**排查**：

1. 确认后端 `llm_service.py` 中 `stream=True`
2. 确认 DeepSeek API 支持流式（`deepseek-chat` 模型支持）
3. 确认前端使用 `fetch + ReadableStream` 方式（非 EventSource）

### 症状3：停止生成按钮无效

**排查**：

1. 确认前端 `conversations.ts` 中 `createChatSSE` 返回了 `AbortController`
2. 确认 chat store 中正确调用了 `controller.abort()`
3. 确认后端正确处理了客户端断开连接

### 症状4：SSE 连接一段时间后断开

**原因**：超时设置。

**解决**：修改 `.env` 中 `SSE_TIMEOUT_MS` 参数，增大超时时间（默认120000ms = 2分钟）。

```bash
SSE_TIMEOUT_MS=300000   # 5分钟
```

## 7. Excel 导出异常

### 症状1：导出文件损坏或无法打开

**原因**：数据编码问题或 pandas 写入异常。

**排查**：
1. 检查 `export_service.py` 中的导出逻辑
2. 确认 `pandas` 和 `openpyxl` 版本正确
3. 查看后端日志中的异常堆栈

### 症状2：Token 明细列缺失

**原因**：messages 表中 `input_tokens` / `output_tokens` 字段值为0或 null。

**排查**：
1. 检查对话是否正常完成（`message` status 为正常）
2. 确认 DeepSeek API 响应中包含 `usage` 字段
3. 查看 `token_usage` 表是否有对应记录

### 症状3：中文乱码

**原因**：编码问题。

**解决**：确认 openpyxl 写入时使用 UTF-8 编码，前端下载时设置正确 Content-Type。

```python
# 后端确保响应头
response.headers["Content-Type"] = "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
response.headers["Content-Disposition"] = "attachment; filename*=UTF-8''报表.xlsx"
```

## 8. Token 费用计算不显示

### 症状1：报表页面费用为 0

**排查**：

1. 检查 `token_usage` 表是否有数据：
```sql
SELECT * FROM token_usage ORDER BY created_at DESC LIMIT 10;
```

2. 检查 `.env` 中单价是否正确设置：
```bash
TONGYI_EMBEDDING_TOKEN_PRICE=0.0008
DEEPSEEK_INPUT_TOKEN_PRICE=0.0010
DEEPSEEK_OUTPUT_TOKEN_PRICE=0.0020
```

### 症状2：修改 .env 单价后费用不变

**原因**：后端未重启，或缓存未刷新。

**解决**：
1. 重启后端服务
2. 刷新前端报表页面
3. 报表为实时计算，无需重启（代码中直接读取 `settings` 对象）

### 症状3：费用报表 SQL 报错

**原因**：可能是 `token_usage` 表外键约束问题。

**解决**：
```sql
-- 检查表结构
SHOW CREATE TABLE token_usage;

-- 如果需要重建
DROP TABLE IF EXISTS token_usage;
-- 然后重启后端自动建表
```

## 9. 前端页面白屏/路由404

### 症状1：访问 http://localhost:5173 白屏

**排查**：

1. 浏览器 F12 → Console 查看 JS 错误
2. 确认 `npm install` 已成功执行
3. 清空浏览器缓存后重试

### 症状2：页面跳转 404

**原因**：Vue Router history 模式，Vite 开发模式下通常不会有此问题。

**解决**：
- 开发模式：Vite 自动处理路由回退
- 生产模式：需配置 Nginx `try_files $uri $uri/ /index.html`

### 症状3：API 请求 404

**原因**：Vite 代理未生效，或请求路径错误。

**排查**：
1. 确认前端请求路径以 `/api` 开头
2. 确认后端对应路由已注册
3. 查看浏览器 Network → 请求 URL 是否正确

## 10. 文件上传失败

### 症状1：上传返回 413

**原因**：文件超过大小限制。

**解决**：修改 `.env` 中 `UPLOAD_MAX_SIZE_MB=100`（默认50MB）。

### 症状2：上传后状态始终 pending

**原因**：文档解析/向量化异步任务失败。

**排查**：
1. 查看后端日志中的错误信息
2. 确认通义 API Key 有效且有余额
3. 确认 Milvus 连接正常
4. 检查文件格式是否在支持列表中

### 症状3：不支持的文件格式

**支持格式**：`pdf, docx, doc, pptx, ppt, txt, md, xlsx, xls`

如需扩展，修改 `.env` 中 `UPLOAD_ALLOWED_EXTENSIONS`。

   - MySQL 版本 (`mysql --version`)

   - 前端浏览器 Console 错误
